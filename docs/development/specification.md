# 仕様

本ドキュメントは、現行実装における認証、検索、対象解決、外部実行、設定保存の契約を記述する。実装前の設計案で未実装の要件は、実装済みの動作として扱わない。

## 公開インターフェース

コマンド構文、検索の一致条件、一覧出力と終了コードは [コマンド](../usage/commands.md)、設定キーと優先順位は [設定](../usage/configuration.md)、SSH の操作と制約は [SSH とファイル転送](../usage/ssh.md) を参照。

## 認証経路

ssmm プロファイルは検索範囲と SSH の既定値を選択し、AWS プロファイルは認証設定を選択する。AWS プロファイルは CLI の `-p`、`-s` で選択した ssmm 設定の `aws_profile`、環境変数、通常の認証情報取得の順に解決する。ssmm プロファイルを選択しない実行では設定ファイルを読み込まない。解決済みの AWS プロファイルは名前と指定元の組で保持する。指定元を失うと、SDK と CLI が明示プロファイルと環境変数を扱う経路を区別できなくなるためである。

指定元ごとの動作を、以下にまとめる。

| 指定元 | SDK の設定 | AWS CLI の起動 |
| --- | --- | --- |
| `flag` | CLI で指定した AWS プロファイルを明示指定 | `--profile` を渡し、子の `AWS_PROFILE` を除去 |
| `config` | ssmm 設定に保存した AWS プロファイルを明示指定 | `--profile` を渡し、子の `AWS_PROFILE` を除去 |
| `env` | `AWS_PROFILE` を維持 | `--profile` を付けず `AWS_PROFILE` を維持 |
| `default` | 標準の認証情報取得を使用 | `--profile` を付けず、子の `AWS_PROFILE` を除去 |

`AWS_DEFAULT_PROFILE` は SDK 設定のロード時と子プロセスの環境から除去する。SDK のロードでは、プロセス環境の一時変更を mutex で保護し、ロード終了後に復元する。明示プロファイルでもアクセスキーなどの環境変数を ssmm 独自の認証情報に変換しない。

プロファイルの存在確認は `AWS_CONFIG_FILE` と `AWS_SHARED_CREDENTIALS_FILE` を反映する。SSO ログインや MFA トークン入力を行う独自 UI は実装していない。

## 検索範囲

検索開始前に `DescribeRegions` を `AllRegions=false` で呼び出す。明示した検索範囲は有効なリージョンと照合し、範囲がなければ取得した一覧をソートして使う。`--region` の指定は保存した `regions` の意味検証より優先するが、TOML の構文・型・未知キーの検査は省略しない。

明示範囲がある場合、リージョン一覧の取得にはその先頭のリージョンを使う。範囲がない場合は AWS SDK が読み込んだリージョン、未設定なら `us-east-1` を使う。

通常の `connect`、`ssh`、`scp` は、ID とリージョンを指定しても検索を行う。公開 `proxy` で ID とリージョンを直接指定した経路と、ラッパーからの内部 proxy だけが検索を省略する。公開経路は CLI フラグと選択した ssmm 設定から AWS プロファイルを解決する。内部経路は検索時に確定した AWS プロファイルを引き継ぎ、設定を再読込しない。

## インベントリ

### 取得の順序と並行数

最大 4 リージョンを並行処理する。1 リージョン内では EC2 の全ページを取得し、該当行がある場合に SSM の全ページを取得する。EC2 が 0 件、または EC2 取得が失敗したリージョンでは SSM をスキップする。

EC2 の対象状態は `pending`、`running`、`shutting-down`、`stopping`、`stopped` である。Name とタグに `*` または `?` を含む場合、その条件を AWS のフィルタへ渡さず、取得後の完全一致で照合する。通常のフィルタを API に渡した場合も、取得後に照合する。

EC2、SSM の各ページとリージョン列挙には、それぞれ 30 秒のタイムアウトを設ける。SDK のリトライ設定は既定値を使う。ページが空でも次トークンがあれば続行し、同じトークンが再登場した場合は取得失敗とする。

### スナップショット

取得側はページを複製してイベントとして送信する。集約処理はリージョンと ID の組で EC2 を保持し、Name、リージョン、ID の順に並べたスナップショットを発行する。開始時点では空の検索中スナップショットを発行する。

通知チャネルのバッファは 1 件であり、未消費の通知は新しいスナップショットで置換する。読み取り側は全リビジョンの受信を前提としてはいけない。

検索状態の意味を、以下にまとめる。

| 項目 | 意味 |
| --- | --- |
| `Generation` | 検索の世代。対話画面での再検索ごとに増加 |
| `Revision` | 同じ世代のスナップショットの連番 |
| `EC2Complete` | 範囲内の全リージョンで EC2 取得が成功 |
| `Finished` | 全リージョンの EC2 と SSM の処理が終了状態 |
| `Canceled` | 検索の context がキャンセル済み |

完了は全 API の同時点での結果や、接続開始時点での状態を保証しない。対象確定後は検索時に得た ID とリージョンを固定する。

### SSM 状態の確定

SSM の途中ページは集約処理内で蓄積する。成功時だけ EC2 の行へ反映し、応答にない ID を `NotReported` とする。取得が途中で失敗した場合は、そのリージョンの全行を `Unknown` とする。SSM API が報告した `Inactive` は `ConnectionLost` に変換する。

### 更新と終了

対話画面での更新、選択、キャンセルでは、現在の検索をキャンセルして終了通知を待つ。更新時はその後に次の世代を開始する。CLI は選択結果の世代が現在の検索と一致することを確認する。

## 対象解決

対象確定の条件を、以下にまとめる。

| 経路 | 条件 |
| --- | --- |
| 対話選択 | 選択したキーが現在の候補に存在し、EC2 が `running` |
| 非対話検索・通常の proxy 検索 | `Finished` と `EC2Complete` が真、候補が 1 件、EC2 が `running` |
| ID とリージョンによる直接 proxy | プロファイル検証と接続計画の検証。インベントリは取得しない |

候補数の判定に停止中のインスタンスも含める。SSM 状態は接続可否の条件に含めない。対話選択は EC2 取得の部分失敗や未完了を許容するが、自動的な一意判定は許容しない。

端末の有無は標準入出力の TTY 判定ではなく `/dev/tty` を開けるかで決定する。対話画面はそのファイルを使い、子プロセスへ渡す標準入出力と分離する。

## 外部コマンド

### 実行計画

通常のシェル接続は `aws ssm start-session --target ID --region REGION` を使用する。SSH 用の proxy は追加で `--document-name AWS-StartSSHSession` と、ポートを表す JSON の `--parameters` を指定する。

SSH と SCP の計画は、固定した ID、リージョン、ポート、プロファイル名と指定元を内部 proxy に渡す。内部用の `--internal-profile-source` はヘルプに公開しない。内部 proxy は ID、リージョン、ポート、指定元と環境変数の整合性を検証する。

ラッパーの `ProxyCommand` では固定引数の `%` をエスケープし、その後にシェル用の引用を行う。通常の子プロセスは引数配列で起動する。シェルの解釈が加わるのは OpenSSH の `ProxyCommand` である。

子プロセスでは `AWS_PAGER` を空文字列、`AWS_CLI_AUTO_PROMPT` を `off` にする。プロファイル関連の環境変数は認証経路の表に従う。AWS CLI や plugin のエラーメッセージを解析して AWS SDK のエラー型へ変換する処理はない。

### プロセスとシグナル

Unix の実行処理は子に専用プロセスグループを割り当てる。通常の接続では、操作可能な標準入力端末があればフォアグラウンドを子へ渡し、終了時に復元する。proxy は端末のフォアグラウンドを取得しない。

親が受け取った SIGHUP、SIGTERM、SIGINT を子のグループに転送する。context のキャンセルは SIGTERM に変換する。終了要求後の猶予は既定で 2 秒であり、終了しなければ SIGKILL を送る。直接の子の終了後も同じグループの残存プロセスを終了処理の対象とする。

終了コードは外部コマンドから引き継ぐ。Unix のシグナル終了は `128 + シグナル番号` に変換する。

## 設定保存

### 読み込みと検証

通常の読み込みでは、TOML の構文、型、未知キー、設定内のプロファイル名を検証する。リージョンと SSH の意味検証は、検索時に選択したプロファイルに対して行う。設定保存時には全プロファイルを検証する。

### 競合と書き込み

編集開始時に、更新対象の内容・存在・モード・シンボリックリンク解決先を保存する。`init` の更新対象は ssmm 設定だけであり、`--ssh` を指定しても SSH ファイルは読み書きしない。`ssh-config create` / `delete` は管理対象 SSH ファイルと SSH の本体設定も更新対象とする。コミット時にファイルロックを取得し、開始時点との比較で変更を検出した場合は保存を中止する。

全設定を検証し、SSH ファイルが更新対象の場合は SSH 設定も生成する。保存順は設定ファイル、管理対象 SSH ファイル、SSH 本体設定とし、更新対象のファイルだけを保存する。各ファイルは同じディレクトリの一時ファイルへ書き込み、同期、rename、ディレクトリ同期を行う。シンボリックリンクの場合は解決先を置換する。

複数ファイル全体のトランザクションではない。途中失敗では成功済みファイルを維持し、ファイル別の保存結果を返す。設定と管理対象 SSH ファイルは `0600`、既存の SSH 本体設定は元のモードを使う。新規ディレクトリは `0700` で作成する。

### SSH Include

管理対象パスと一致する単独の `Include` 行を識別する。該当行がなければ先頭に追加し、重複する該当行は 1 件にする。既存の該当行がある場合は、その位置を維持する。すべてのプロファイルで SSH 連携を無効にした場合は該当行を削除する。

SSH 設定全体を構文木として解析する実装ではない。ワイルドカードの Include、複数パスを含む行、表記の異なる同等の指定は同じ管理対象行として扱わない。

## 設計案との差異

実装前の設計記録を参照する際に区別が必要な事項を、以下にまとめる。

| 項目 | 現行実装 |
| --- | --- |
| TARGET 指定時の自動接続 | 操作端末がある場合は TUI で Enter を要求する |
| ID とリージョン指定時の検索省略 | proxy の直接指定と内部呼び出しに限る |
| 検索中の TUI | 行と全体の進行状態を表示する。リージョン別のエラー詳細は表示しない |
| アプリケーション層への集約 | CLI が対話操作、接続計画の呼び出し、外部実行、初期設定の入力を制御する |
| プロファイルの選択 | ssmm プロファイルと AWS プロファイルを分離し、`aws_profile` で対応づける |
| 標準 SSH 設定の作成・削除 | `ssh-config create` / `delete` で生成対象を切り替える。`init` は AWS プロファイル名と検索リージョンを更新し、`--ssh` 指定時だけ SSH の既定値も更新する |
| 入れ子のプロセスの終了猶予 | proxy と外側のラッパーに別の猶予時間を設定していない |
| エラー分類 | CLI 経路で統一されておらず、入力起因でも終了コード 1 の場合がある |
| 未知のリージョン形式 | 明示値の検証は正規表現を使う。有効な AWS リージョンであっても形式によって拒否する可能性がある |

未実装の設計を追加する場合は、動作と検証を整えてから公開仕様と利用ガイドを更新する。
